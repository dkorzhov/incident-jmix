IT INCIDENTTRACKER

Концепция небольшого, законченного веб-приложения для управления ИТ-инцидентами

Проект для практического эксперимента с агентской разработкой: от требований до backend, frontend, тестирования и запуска.

Параметр

Решение

Назначение

Единое рабочее место небольшой ИТ-команды для регистрации и обработки инцидентов

Объём

MVP: реестр, создание, карточка, статусы, комментарии, история, Dashboard

Стек

FastAPI + React + TypeScript + PostgreSQL + Docker Compose

Результат

Локально запускаемое приложение с API, UI, тестами и инструкцией

Цель проектаПроверить не только способность AI генерировать код, но и способность нескольких агентов согласованно пройти полный цикл разработки.

1. Бизнес-контекст

В небольшой ИТ-службе инциденты часто фиксируются в чатах, почте и таблицах. Сложно быстро определить владельца проблемы, текущий статус, уже выполненные действия и общий объём открытых обращений.

IT Incident Tracker собирает эти сведения в одном месте. Примеры инцидентов: недоступен VPN, не работает корпоративная почта, недоступен внутренний портал, медленно отвечает база данных, не работает рабочее место.

4. Бизнес-правила

Текущий статус

Действие

Результат

New

Взять в работу

In Progress

In Progress

Отметить решённым с обязательным Resolution

Resolved

Resolved

Закрыть

Closed

Нельзя закрыть инцидент напрямую из New или In Progress.

Для перехода в Resolved обязательно заполнить Resolution — описание решения.

После Closed нельзя редактировать инцидент и добавлять комментарии.

Удаление инцидентов не предусмотрено.

Каждое значимое изменение автоматически записывается в историю.

Все проверки бизнес-правил выполняются на backend, а не только в интерфейсе.

6. Что не входит в MVP

Полноценная авторизация, SSO и сложная ролевая модель.

SLA, эскалации и календарь поддержки.

Интеграции с почтой, Teams, Slack или Telegram.

Автоматическая AI-классификация и генерация решений.

Управление Problem, Change и Configuration Items.

Ограничение первой версииДля локального MVP текущий пользователь выбирается из заранее загруженного списка. Это упрощение не следует переносить в промышленную систему без проектирования аутентификации и авторизации.

7. Как понять, что MVP готов

Приложение запускается одной командой docker compose up.

Пользователь может создать, найти, назначить и обработать инцидент.

Недопустимые переходы статусов блокируются сервером.

Решение обязательно при переводе в Resolved.

История и комментарии отображаются в карточке.

Dashboard считает показатели по данным БД.

Есть автоматические backend-тесты и минимум один E2E-сценарий.

README описывает запуск, миграции и демонстрационные данные.
